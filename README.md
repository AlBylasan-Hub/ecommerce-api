# E-commerce REST API - التاسك التدريبي الثاني

## معلومات الطالب

- **الاسم الرباعي:** البيلسان مصلح فلاح الضمور
- **الرقم الجامعي:** 120222231108
- **البرنامج:** برنامج التدريب العملي - BATMAN TECHNOLOGY
- **المرحلة:** المرحلة الثانية - بناء REST API باستخدام Node.js و Express والاتصال بـ Neon PostgreSQL

## وصف المشروع

هذا المشروع عبارة عن واجهة برمجية (REST API) لمتجر إلكتروني، مبنية باستخدام Node.js و
Express ومتصلة بقاعدة البيانات التي أنشأتها في المرحلة الأولى على Neon PostgreSQL.

الـ API يستقبل طلبات HTTP، ينفّذ عمليات على قاعدة البيانات، ويرجع النتيجة بصيغة JSON ثابتة
الشكل. كل الاستعلامات التي تستقبل قيمًا من المستخدم تستخدم `$1` و `$2` بدل دمج النص مباشرة،
وذلك للحماية من SQL Injection.

## المتطلبات قبل التشغيل

- Node.js مثبت على الجهاز.
- مشروع Neon يحتوي على جداول `users` و `categories` و `products` من المرحلة الأولى.
- Postman لاختبار الـ endpoints.

## خطوات التشغيل

1. تثبيت الحزم:

```bash
npm install
```

2. إنشاء ملف `.env` في جذر المشروع بنسخ محتوى `.env.example`، ثم وضع رابط الاتصال الحقيقي
   من Neon مكان القيمة الوهمية:

```
PORT=3000
DATABASE_URL=postgresql://username:password@host/database?sslmode=require
```

3. تشغيل المشروع في وضع التطوير:

```bash
npm run dev
```

أو التشغيل العادي:

```bash
npm start
```

4. عند نجاح التشغيل تظهر في الطرفية الرسائل التالية:

```
Server is running on port 3000
Database connected successfully
```

5. للتأكد من عمل الـ API افتح Postman وأرسل `GET http://localhost:3000` ويجب أن ترجع:

```json
{ "success": true, "message": "E-commerce API is running" }
```

## الـ Endpoints

عنوان الأساس: `http://localhost:3000`

### المنتجات

| الطريقة | المسار | الوظيفة |

## أمثلة على الطلبات

إضافة منتج - `POST /api/products`

```json
{
  "category_id": 1,
  "name": "Wireless Mouse",
  "description": "Rechargeable wireless mouse",
  "price": 18.5,
  "stock_quantity": 20,
  "sku": "MOUSE-001"
}
```

إضافة مستخدم - `POST /api/users`

```json
{
  "full_name": "Ahmad Test User",
  "email": "ahmad.test@example.com",
  "phone": "0791234567",
  "role": "customer"
}
```

تغيير حالة مستخدم - `PATCH /api/users/:id/status`

```json
{
  "is_active": false
}
```

## شكل الاستجابة

كل الردود لها نفس الشكل. في حالة النجاح:

```json
{
  "success": true,
  "message": "Product created successfully",
  "data": { "id": 21, "name": "Wireless Mouse" }
}
```

وفي حالة الخطأ:

```json
{
  "success": false,
  "message": "Product not found"
}
```

## أكواد الحالة المستخدمة

| الكود | متى يُستخدم |
|---|---|
| 200 | نجاح عملية القراءة أو التعديل. |
| 201 | تم إنشاء سجل جديد بنجاح. |
| 400 | بيانات ناقصة أو غير صالحة، مثل سعر سالب أو JSON غير مكتمل. |
| 404 | السجل أو المسار غير موجود. |
| 409 | تعارض في قيمة UNIQUE مثل تكرار الـ SKU أو البريد الإلكتروني. |
| 500 | خطأ غير متوقع في السيرفر. |

## التحقق من المدخلات ومعالجة الأخطاء

- التحقق من الحقول المطلوبة قبل تنفيذ أي استعلام على قاعدة البيانات.
- تحويل الـ id في المسار إلى رقم والتأكد أنه عدد صحيح موجب.
- السعر يجب أن يكون أكبر من صفر، والكمية لا تكون سالبة.
- التقاط رمز الخطأ `23505` من PostgreSQL وإرجاع 409 عند تكرار قيمة UNIQUE.
- التقاط رمز الخطأ `23503` وإرجاع 400 عندما يكون التصنيف غير موجود.
- إرجاع 404 عندما لا يرجع الاستعلام أي صف.
- طباعة الخطأ التقني في الطرفية فقط، وإرجاع رسالة واضحة وآمنة للمستخدم بدون تفاصيل داخلية.

## اختبار الـ API باستخدام Postman

1. افتح Postman واضغط **Import**.
2. استورد الملفين من مجلد `postman/`:
   - `Ecommerce_API.postman_collection.json`
   - `Ecommerce_API.postman_environment.json`
3. اختر البيئة `Ecommerce API Local` من القائمة أعلى اليمين، وفيها المتغير `baseUrl` بقيمة
   `http://localhost:3000`.
4. تأكد أن السيرفر يعمل، ثم شغّل الطلبات واحدًا واحدًا أو استخدم **Run collection**.

الـ Collection تحتوي على 22 طلبًا: الطلبات من 1 إلى 16 هي الاختبارات الإلزامية المطلوبة،
والطلبات من 17 إلى 22 تغطي باقي الـ endpoints.

## المشاكل التي واجهتني وحلولها

**المشكلة الأولى:** عند أول تشغيل ظهر الخطأ `relation "products" does not exist` رغم أن رسالة
`Database connected successfully` كانت تظهر بشكل طبيعي.

**الحل:** الاتصال بقاعدة البيانات كان سليمًا، لكن الجداول لم تكن موجودة في تلك اللحظة لأنني
كنت قد حذفتها لإعادة تشغيل ملفات SQL. بعد إعادة إنشاء الجداول عملت جميع الاستعلامات. تعلمت
من هذه المشكلة أن نجاح الاتصال شيء ووجود الجداول شيء آخر.

**المشكلة الثانية:** عند إرسال JSON ناقص من Postman كان Express يرجع صفحة خطأ HTML بدل رسالة
JSON، وهذا يكسر شكل الاستجابة الموحّد.

**الحل:** أضفت في `errorHandler.js` تحققًا من نوع الخطأ `entity.parse.failed` وأرجعت
حالة 400 برسالة JSON واضحة.

**المشكلة الثالثة:** عند تكرار الـ SKU كان السيرفر يرجع 500 بدل 409.

**الحل:** التقطت رمز خطأ PostgreSQL `23505` داخل `catch` وأرجعت 409 مع رسالة توضّح أن القيمة
مكررة.

## الأمان

- ملف `.env` مضاف إلى `.gitignore` ولا يتم رفعه إطلاقًا.
- ملف `.env.example` يحتوي على أسماء المتغيرات فقط بدون أي بيانات حقيقية.
- رابط الاتصال بـ Neon وكلمة مرور قاعدة البيانات غير موجودين في هذا الملف ولا في أي ملف
  من ملفات المشروع.
- جميع الاستعلامات تستخدم `$1` و `$2` بدل دمج مدخلات المستخدم داخل نص SQL.
- رسائل الأخطاء المرسلة للمستخدم لا تحتوي على تفاصيل تقنية أو بيانات اتصال.
